# PRD: Сайт ТОО «N-VECTOR Consulting Services»

**Статус:** V1 реализован (статический сайт готов), подключение к Google Таблице и публикация — в процессе.
**Владелец:** Нагима Набиева, основатель и генеральный директор N-VECTOR.

---

## 1. Контекст и цель

У компании уже есть сайт n-vector.net (статический HTML/CSS/JS, развёрнутый через Netlify). Текущий проект — **отдельный, самостоятельный сайт**, не развитие существующей версии: разрабатывается с нуля, с новой структурой и новым функционалом для самостоятельного пополнения контента.

**Цель:** публично доступный сайт компании, который можно пополнять новой информацией (команда, проекты, мероприятия, программы поддержки) без участия разработчика — через кнопку «+».

---

## 3. Пользователи и права доступа

| Роль | Доступ |
|---|---|
| Нагима (админ) и сотрудники с ключом | Админ-панель `admin.html`: добавление, редактирование, публикация/скрытие, удаление записей |
| Посетители сайта | Пользовательская версия — только просмотр опубликованного контента |

Вход в админ-панель — по ключу администратора (`ADMIN_KEY` в свойствах Apps Script). На публичных страницах кнопок редактирования нет.

## 4. Функциональные требования

### 4.1 Управление контентом (админ-панель)
- Отдельная страница `admin.html`, ссылки на неё с сайта нет; закрыта от поисковиков (`noindex`).
- Вкладки разделов «Команда», «Проекты», «Мероприятия», «Программы поддержки» со счётчиками записей и черновиков.
- У каждой записи кнопки: «Изменить», «Опубликовать / Скрыть с сайта», «Удалить» (подтверждение повторным нажатием).
- Редактор с вкладками RU / EN / KZ для текстов и общими полями (дата, ссылка, фото, тип программы); переключатель «Опубликовано на сайте».
- Поиск и фильтр «Все / Опубликованные / Черновики».
- Без подключённой таблицы — демо-режим: правки в браузере, предпросмотр сайта (`?preview=1`), выгрузка готового `fallback.js`.
- Каждый раздел — отдельный лист в таблице, со своим набором полей.

### 4.2 Модель данных

**team** (Команда): `id, name, role, bio, tags, photo, email, status` (`tags` — компетенции через запятую, `photo` — ссылка на фото)
**projects** (Проекты): `id, name, tag, description, year, link, status`
**events** (Мероприятия): `id, title, date, location, description, link, status`
**programs** (Программы поддержки): `id, type, name, description, deadline, link, status`

`status` = `pending` (на модерации) или `published` (опубликовано).
`type` для программ: Конкурс / Обучение / Инкубация-Акселерация / Финансирование.

### 4.3 Публикация
- Новая запись по умолчанию — черновик (`pending`) и не видна посетителям; публикуется кнопкой или переключателем в админке.
- Любое изменение данных требует ключ администратора — проверка на стороне Apps Script.
- Каждое поле переводится полями `*_en` / `*_kz`; пустой перевод — на сайте показывается русский текст.

### 4.4 Отображение данных
- Сайт загружает только записи со `status = published`.
- Если бэкенд (Google Таблица) ещё не подключён или недоступен — сайт показывает резервные локальные данные, чтобы не оставаться пустым.

### 4.5 Программы поддержки
- Каждая запись — название, тип, описание, (опционально) дедлайн подачи заявки, и обязательная ссылка на официальный сайт программы.
- Стартовый набор данных включает реальные действующие программы (QazInnovations, Astana Hub) с проверенными ссылками.

## 5. Технические требования

| Компонент | Решение |
|---|---|
| Фронтенд | Статические HTML/CSS/JS, без сборки, 5 страниц |
| Хранилище данных | Google Таблицы (4 листа по числу разделов) |
| API-слой | Google Apps Script (Web App): `doGet` отдаёт опубликованные записи листа; `doPost` — действия админки (`login`, `list`, `create`, `update`, `remove`) только с ключом `ADMIN_KEY` |
| Локальный резерв | JSON-файлы в `data/`, используются, пока Google-бэкенд не подключён или недоступен |
| Хостинг | Netlify (drag-and-drop), как и для текущего сайта |
| Домен | n-vector.net (решение по домену — отдельно, т.к. сайт отдельный от текущей версии) |

**Почему не публикация через встроенный инструмент Claude:** такие страницы работают в песочнице без доступа к внешним API, поэтому Google Таблицы как бэкенд там подключить нельзя. Отсюда — обычный файловый проект для самостоятельного хостинга.

## 6. Требования к дизайну

- Стиль: деловой корпоративный по образцу владельца — тёмная верхняя полоса (контакты, направление, переключатель EN / RU / KZ справа), белая шапка с меню заглавными буквами и кнопкой-«таблеткой» «Связаться».
- Главная: первый экран с фото на всю ширину и светлой подложкой под текстом; три тёмные карточки достижений с круглыми иконками, заходящие на первый экран; сетка услуг с квадратными фото-иконками; ключевой проект; команда; тёмный блок связи; бежевый подвал с логотипом.
- Палитра: графитово-синий #262a36, белый, светлый беж #ece8e2, бежевый подвал #cfc7bc; точечный акцент #1f6f9a. Шрифты: Fira Sans (заголовки), Montserrat (текст) — оба с казахскими буквами.
- Используются фото сайта: сцены (img/scene/), выставки и слайд SeedMaster, фото команды; логотип — img/logo-mark.svg.
- Сдержанное движение по наведению (js/motion.js); отключается на сенсорных экранах и при «уменьшении движения».
- Адаптивность: меню-«бургер» до 1120 px, мобильная версия до 760 px; видимый фокус для клавиатуры.
